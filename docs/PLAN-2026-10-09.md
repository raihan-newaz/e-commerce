# NIX website ও operations উন্নয়ন পরিকল্পনা

## লক্ষ্য ও বর্তমান অবস্থা

এই পরিকল্পনার অগ্রাধিকার **বর্তমান single-store ব্যবসার operations দ্রুত করা**, তারপর landing page ও storefront সহজ এবং নির্ভরযোগ্য করা। Orders, courier integrations, inventory, messaging, Pages এবং Visual Studio ইতিমধ্যে আছে; এগুলো নতুন করে বানানো হবে না। [আজকের audit](D:/Antigravity/NIX%20Order%20manage/docs/WEBSITE-AUDIT-2026-10-09.md) অনুযায়ী কিছু গুরুত্বপূর্ণ নিরাপত্তা ও order-lifecycle সমস্যা ইতিমধ্যে ঠিক হয়েছে, তবে সব authenticated workflow এবং বাস্তব provider callback পরীক্ষা করা হয়নি।

## ধাপে ধাপে কাজ

1. **P0 — পরিবর্তনের আগে সুরক্ষা ও baseline**
   - Database ও uploaded media-এর যাচাইযোগ্য backup নিন; staging database-এ restore পরীক্ষা করুন। Published landing page, checkout configuration, product, order ও courier state-এর snapshot রাখুন।
   - Server, admin ও storefront build; বিদ্যমান builder/audit tests; গুরুত্বপূর্ণ API authorization checks—সব CI-তে চালান। Test কখনো live order, payment, courier booking বা message পাঠাবে না।
   - `docs/unified-pages-plan.md`-এর অসমাপ্ত অংশ ধরে Pages/Studio publication flow-এর regression tests যোগ করুন। Draft save করলে live page অপরিবর্তিত থাকবে; publish ব্যর্থ হলে আগের live revision থাকবে।
   - Security review-তে object-level authorization, role checks, sensitive response fields এবং rate limits অন্তর্ভুক্ত করুন; [OWASP API Security](https://api-security.owasp.org/editions/2023/en/0x10-api-security-risks/) checklist হিসেবে ব্যবহার করুন।

2. **P1 — Operations speed: প্রথম feature release**
   - Orders list-এ বিদ্যমান `assignedToId` ও `priority` ব্যবহার করে **assignee, priority, order age, courier এবং settlement** filter যোগ করুন। Filter URL-এ থাকবে, যাতে staff একই view share বা bookmark করতে পারে। Order details ও list থেকেই অনুমোদিত role assignment/priority বদলাতে পারবে; server validation এবং audit entry থাকবে।
   - একটি **Action Center** দিন: unassigned pending orders, দীর্ঘসময় আটকে থাকা orders, low-stock variations, uncertain courier bookings, return requests ও COD discrepancies। প্রতিটি card সংশ্লিষ্ট filtered list বা order-এ খুলবে; সংখ্যা বাস্তব API data থেকে আসবে।
   - Courier Hub-এ exception queue ও স্পষ্ট next action দেখান। Booking outcome অনিশ্চিত থাকলে “retry” দিয়ে দ্বিতীয় shipment তৈরি করা যাবে না; আগে provider status refresh বা বিদ্যমান resolve flow ব্যবহার করতে হবে।
   - Inventory-তে বর্তমান low-stock view থেকে product/variation detail এবং stock movement history-তে সরাসরি যাওয়ার পথ যোগ করুন। Stock পরিবর্তন কেবল বিদ্যমান server transaction ও movement record দিয়ে হবে।

3. **P2 — Pages, checkout ও storefront update**
   - `/pages`-কে একমাত্র সাধারণ page-management entry করুন। Linked landing page Studio-তে খুলবে; products, delivery, coupon, payment, SEO, preview ও publish একই workflow-তে স্পষ্ট থাকবে। Existing content/system page conversion শেষ না হওয়া পর্যন্ত তাদের বর্তমান editor ও public URL সচল রাখুন।
   - [বিদ্যমান unified Pages পরিকল্পনা](D:/Antigravity/NIX%20Order%20manage/docs/unified-pages-plan.md) অনুসারে content pages ধাপে ধাপে Studio draft-এ convert করুন। Import warning ও preview comparison ছাড়া কোনো live page replace করবেন না। পুরোনো URL, page ID, coupon/order relation, Thank You page এবং `/b/:slug` link বজায় রাখুন।
   - Public checkout-এ একই submit পুনরায় এলে duplicate order ঠেকাতে server-side idempotency যোগ করুন। Browser price নয়, server-এর product, variation, stock, coupon ও delivery calculation চূড়ান্ত হবে।
   - Mobile landing page ও checkout-এ loading, image sizing, focus, button alignment, Bengali typography এবং no-horizontal-overflow যাচাই করুন। বাস্তব traffic-এ [LCP, INP ও CLS](https://web.dev/articles/vitals) পরিমাপ করুন; accessibility review-তে [WCAG 2.2](https://www.w3.org/TR/wcag/) অনুসরণ করুন।

4. **P3 — পরবর্তী growth features**
   - Operations release স্থিতিশীল হওয়ার পরে abandoned-checkout follow-up, campaign attribution ও conversion reporting বিবেচনা করুন। Tracking consent এবং browser/server event deduplication বজায় থাকবে।
   - Facebook, Instagram ও WhatsApp-এর **shared inbox** আলাদা integration project হিসেবে নিন। বিদ্যমান outbound WhatsApp/SMS screen-কে inbound omnichannel inbox বলে দেখাবেন না। Provider access, webhook verification, conversation assignment ও message retention আগে নির্ধারণ করতে হবে।
   - এখন multi-tenant SaaS migration, wholesale database rewrite বা নতুন payment/courier provider এই পরিকল্পনার অংশ নয়।

## Interface, data ও compatibility

- বিদ্যমান order, product, courier ও page records পুনরায় তৈরি করবেন না। Operations-এর নতুন filter/API fields additive হবে; পুরোনো client request আগের মতো চলবে।
- Assignment ও priority mutation-এ server-side role validation, target-user validation ও audit log বাধ্যতামূলক। Exception dashboard বিদ্যমান order/courier data থেকে শুরু হবে; নতুন persistent model কেবল প্রয়োজন প্রমাণ হলে যোগ হবে।
- Checkout idempotency key প্রতি নতুন order attempt-এ আলাদা হবে; একই attempt retry করলে একই ফল ফিরবে, ভিন্ন payload-এ একই key ব্যবহার করলে conflict ফিরবে। Schema পরিবর্তন হলে আগে backup, তারপর staging migration ও rollback rehearsal।
- প্রতিটি phase ছোট release-এ দিন। Published page ও checkout-এর জন্য feature flag বা reversible rollout রাখুন; migration-এর কারণে legacy data মুছবেন না।

## যাচাই ও release gate

- প্রতি release-এ তিনটি production build, server tests, builder tests এবং API authorization tests পাস করতে হবে।
- E2E scenarios: product edit → landing publish → public page → variation/quantity/delivery/coupon → COD order → admin queue → courier dispatch → status/return → stock ও COD reconciliation; draft save ও failed publish-এর পর live page অপরিবর্তিত থাকার পরীক্ষা।
- 320–390px mobile, tablet ও desktop-এ storefront/landing/checkout দেখুন। Keyboard navigation, visible focus, error message এবং Bangla text overflow পরীক্ষা করুন।
- Staging-এ provider sandbox বা signed fixture দিয়ে payment/courier/webhook যাচাই করুন। বাস্তব provider credential দিয়ে production verification কেবল আলাদা নিয়ন্ত্রিত ধাপে হবে।
- কোনো release-এ বিদ্যমান order, public URL, published page, stock বা payment flow regression হলে সেই phase rollback করুন; পরের phase শুরু করবেন না।

**Assumption:** প্রথম লক্ষ্য single-store operations speed। নতুন growth feature-এর চেয়ে existing order ও courier workflow উন্নয়ন এবং non-breaking release বেশি গুরুত্বপূর্ণ।
